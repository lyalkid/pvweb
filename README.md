# Phylo Viewer Web

Просмотр и сравнение филогенетических деревьев целиком в браузере. Приложение
собирается в статику и разворачивается на GitHub Pages бесплатно: сервера,
базы данных и контейнеров нет.

Это браузерная версия проекта `phylo-viewer`, в котором те же экраны работали
поверх FastAPI и PostgreSQL.

## Что умеет

- Проекты: создание, удаление, список.
- Загрузка деревьев файлом и ввод вручную. Форматы: Newick, NEXUS, PhyloXML.
- Просмотр одного дерева: сворачивание узлов, перекорневание, обрезка, обмен
  потомков, лестничная укладка, раскраска, история отмен.
- Текстовый редактор дерева с рабочей копией поверх оригинала.
- Танглограммы: пара деревьев, связи между одноимёнными листьями, подсчёт
  пересечений, оптимизация жадным алгоритмом.
- Сохранение состояния просмотра и настроек: при следующем открытии проект
  выглядит так, как его оставили.
- Экспорт изображений, интерфейс на русском и английском, светлая и тёмная темы.

## Где лежат данные

В IndexedDB того браузера, где открыто приложение. Данные никуда не отправляются
и не синхронизируются между устройствами.

Отсюда два следствия. Очистка данных сайта стирает проекты. Открыв приложение в
другом браузере, вы увидите пустой список.

Страховка от обоих случаев — кнопки на экране проектов:

- **Скачать копию** сохраняет всё содержимое базы в один JSON-файл.
- **Загрузить копию** заменяет текущее содержимое базы этим файлом.

Копию стоит снимать после заметной работы и перед очисткой браузера.

## Локальный запуск

```bash
make install
make dev
```

Приложение откроется на http://127.0.0.1:5173.

Остальные цели показывает `make` без аргументов:

```bash
make build           # сборка в dist/
make build BASE=/pvweb/   # так же, как её делает GitHub Pages
make preview         # просмотр собранной версии
make check           # типы и линтер
make test            # тесты
make ci              # всё вместе, как в workflow
make clean           # удалить dist/
```

## Развёртывание на GitHub Pages

Репозиторий: `git@github.com:lyalkid/pvweb.git`.

Один раз нужно включить публикацию: **Settings → Pages**, в поле **Source**
выбрать **GitHub Actions**. Без этого workflow соберёт проект, но не опубликует.

Дальше достаточно пушить в `master`. Всё остальное делает
[.github/workflows/deploy.yml](.github/workflows/deploy.yml): вызывает
`make install-ci` и `make ci`, то есть проверяет типы, гоняет линтер и тесты,
собирает проект и публикует. Базовый путь подставляется из имени репозитория,
поэтому конфигурацию править не нужно.

Сайт появится по адресу https://lyalkid.github.io/pvweb/.

Адреса страниц хранятся в хеше, например `#/projects/<id>/view`. Это сделано
намеренно: GitHub Pages отдаёт статику и не умеет переписывать произвольный путь
на `index.html`, поэтому обычные пути ломались бы при перезагрузке страницы.

## Чем отличается от серверной версии

Убрано то, что требует сервера.

| Было | Стало |
|---|---|
| Регистрация, вход, JWT | Аутентификации нет, приложение рассчитано на одного человека |
| PostgreSQL | IndexedDB в браузере |
| FastAPI, Docker, nginx, Alembic | Ничего, только статика |
| Резервные копии через `pg_dump` | Выгрузка и загрузка JSON-файла |

Из режимов оптимизации танглограмм остались `auto` и `greedy`. Остальные
требовали рантаймов, которых в браузере нет:

| Режим | Что требовал |
|---|---|
| `rl`, `beam` | PPO-модели PyTorch и stable-baselines3 |
| `step2side`, `stepBothSides` | R и пакет dendextend |
| `shuntan` | scipy и пакет tanglegram |

Ограничение на размер танглограммы поднято с 64 листьев до 256. Прежний порог
существовал потому, что PPO-модели были обучены на 8, 16, 32 и 64 листьях. Без
моделей его держит только время счёта.

Поведение жадного режима не изменилось. В `src/lib/tanglegram-optimizer.test.ts`
лежат 60 эталонных случаев, снятых с серверной реализации на Python: порт
выдаёт те же числа пересечений, те же последовательности действий и те же
выходные строки Newick. Определение формата и подсчёт листьев проверены так же.

## Структура

```
src/
  lib/
    api.ts                    локальный API поверх IndexedDB, заменяет HTTP-клиент
    storage/                  обёртка над IndexedDB и типы записей
    tanglegram-optimizer.ts   жадная оптимизация, порт с сервера
    tree-content.ts           определение формата и подсчёт листьев, порт с сервера
    backup.ts                 выгрузка и загрузка резервной копии
  components/, screens/, hooks/, i18n/, styles/
packages/
  phylo-tree-lib/             разбор, укладка и отрисовка деревьев
```

Библиотека `phylo-tree-lib` подключается напрямую из исходников через алиас Vite,
поэтому отдельная сборка библиотеки не нужна.
